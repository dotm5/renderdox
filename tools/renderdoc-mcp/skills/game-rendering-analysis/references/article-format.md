# 图文与 HLSL 文章格式

由 LLM 编写连贯的解释；MCP 不负责生成语义结论。默认使用用户语言。

## 全文结构

先说明当前捕获、角色/场景、API、分辨率和观察范围，附全景定位图与流程概览。说明 LLM 从哪些信号发现候选、为什么选择这些机制深入，再按发现组织章节；不要套用固定的 SSS/Bloom/LUT 等目录。专项请求按指定范围组织并保留必要上下游。候选笔记可列发现线索、研究价值、Pass/EID、资源/Shader 和调查状态，保留值得后续研究的项；不要求列出所有常见效果，也不把未调查写成不存在。最后列未验证部分及复查入口。读者应能直接理解算法，不需要阅读工具日志。

## 每个效果的一组材料

1. **现象和问题**：最终画面局部，圈出分析位置，说明要验证什么。
2. **输入**：纹理接触表/通道图/数组层、采样器和关键参数。颜色图与数值遮罩分别显示。
3. **算法**：短流程图、数学关系和分模块 HLSL；代码使用语义名并注明绑定/常量/指令对照。
4. **中间量**：选对有解释价值的量，如阈值、权重、UV、法线、粗糙度，不机械输出所有寄存器。
5. **对照**：同 ROI 原始、关闭/替换单项、差分；参数扫描附取值。无法生成则标缺失。
6. **结论**：这项效果怎样影响最终图、是否实际执行、结论来源及剩余疑问。

前面五项按案例删减；不要制造每节都有六图的假完整性。篇章可以解释计算顺序，也可以按问题组织，但代码依赖要保留。

## HLSL 与图像标注

代码块注明 `原始源码 / 经验证的等效重建 / 说明性伪代码`。长 Shader 只放关键段并链接完整文件。符号名是作者命名时注明；不要把 GLSL 的 mix、vec3、texture 或伪代码的循环包装成可编译 HLSL。

每幅图用人类可读名称和编号，附捕获哈希、EID、资源/目标、mip/slice/sample、通道、ROI、编码/显示转换和实验状态。数值遮罩使用说明过的显示映射；法线显示区分空间和范围。HDR、LUT 后输出及 PNG 预览不能套用同一 sRGB 处理。

区分两组状态：事实为 **确认 / 推断 / 未知**；重建为 **精确 / 指定容差内等效 / 近似**。反汇编有分支但当前未执行时，写成潜在能力；推测的纹理通道名不要冒充原始引擎命名。

## 复查与交付

用宿主文件工具保存 REPORT.md/HTML、images/、shaders/ 和 experiments/；维持相对链接。若只可调用 MCP 而不能写宿主文件，则在回复中撰写正文，并将解释通过 annotate_capture 记录，再导出 MCP 证据包。

`export_analysis_bundle` 当前自动收集 MCP 注册的产物，不自动导入宿主生成的代码和解释图；由 LLM/宿主将两者合并并检验文件、相对链接及 ZIP。性能数字标明回放条件，不能把累计 draw counter 图当真实 GPU 调度时间轴。
